# ADR-001: Вибір Fastify як HTTP-фреймворку

**Статус:** Прийнято  
**Дата:** 2026-04-12  
**Автор:** Ivan (flocky674)

## Контекст

Сервіс **github-release-notifier** надає REST API для підписки на email-сповіщення про нові релізи GitHub-репозиторіїв. Потрібно:

- обробляти запити підписки, підтвердження та відписки;
- віддавати статичну сторінку та health-check;
- централізовано обробляти помилки (валідація, доменні `AppError`, 500);
- за потреби захищати API ключем (`X-API-Key`) через глобальний хук.


## Розглянуті варіанти

### 1. Nest.js

- **Плюси:** модульна структура, DI, декоратори, зручно для великих команд і довгоживучих продуктів.
- **Мінуси:** більше boilerplate, вища вхідний поріг; для невеликого API з кількома ендпоінтами виглядає надмірним.

### 2. Express

- **Плюси:** найпоширеніший стек, багато прикладів і middleware.
- **Мінуси:** менш виразна схема валідації «з коробки»; для typed-підходу потрібні додаткові обгортки; продуктивність нижча за Fastify на типових сценаріях.

### 3. Fastify

- **Плюси:** висока швидкість, низький overhead, зручні lifecycle hooks (`onRequest`, `setErrorHandler`), плагіни (`@fastify/static`, swagger).
- **Мінуси:** менше «готової» архітектури, ніж у Nest — структуру модулів треба визначати самостійно.

## Прийняте рішення

Обрано **Fastify**.

Збірка застосунку винесена в `buildApp()` (`src/app.ts`): створення інстансу, опційний хук перевірки API key для непублічних шляхів, глобальний error handler, реєстрація статики та маршрутів підписок. Залежності сервісів (репозиторії, GitHub, notifier) підключаються явно при старті — без фреймворкового DI-контейнера.


## Наслідки

**Позитивні:**

- Швидкий старт і читабельний код для невеликої кодової бази.
- Зручні хуки для cross-cutting concerns (авторизація по API key, єдиний формат помилок).
- Добра інтеграція з екосистемою Node.js (плагіни, TypeScript).

**Негативні:**

- При зростанні проєкту доведеться самостійно вводити правила модульності (шари controller / service / repository уже закладені вручну).
- Менше «стандартних» патернів курсу/корпорації, ніж у Nest — новим учасникам команди потрібен короткий onboarding по структурі репозиторію.
